2473: ### D-085 — Unpack `Tuple`/`NamedTuple` fields as container children
2474: 
2475: **Status.** ratified
2476: 
2477: **Position.** Container children: `Tuple`/`NamedTuple` fields with
2478: all-component elements unpack as children (`"field/1"`/`"field/key"` path
2479: segments, declaration-order layout); containers are transparent grouping — no
2480: contract, no `connections`, no rate scope.
2481: 
2482: **Spec.** [§8.8][s8-8], [§14.9][s14-9]
2483: 
2484: **Rationale.** Elements are the *parent's* children, wired/exported/rated by
2485: element name; parametric rosters (`Formation{NT <: NamedTuple}`) compose per
2486: instantiation via [§8.8][s8-8] generic holding, wires generated by comprehension
2487: (arity-via-computed-contracts at structure scale; [§14.9][s14-9] swarms and
2488: `at`-mounting consume directly); mixed component/non-component elements = build
2489: error, zero-component containers = inert data, no container nesting (first
2490: cut), empty containers legal, `rates` keys = element names with bare-field-name
2491: uniform-`K` sugar.
2492: 
2493: **Rejected.**
2494: - *One-field-per-child + programmatic struct generation:* roster frozen in
2495:   source text; fights the no-macros stance.
2496: - *Homogeneous-`NTuple`-only:* the per-element complexity objection was hollow
2497:   — element types are static either way; named and mixed rosters are the [§14.9][s14-9]
2498:   case, user call.
2499: - *`Vector{C}` children:* runtime-sized, mutable — breaks the immutable tree
2500:   and the type-stable layout.
2501: - *Containers as anonymous assemblies:* a second composition boundary without a
2502:   type — wiring must stay with the parent.
