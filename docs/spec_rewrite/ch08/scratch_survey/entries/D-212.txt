7579: ### D-212 — Refuse the transparent bare key that shadows a sibling container field
7580: 
7581: **Status.** ratified
7582: 
7583: **Position.** Completing [D-211][d-211]'s collision family (annotating [D-211][d-211]): a
7584: name-transparent element's bare key equal to the name of a sibling container
7585: field that contributes children is a build error naming both parties, although
7586: no child bears that name — the key shadows the container's `"field/key"`
7587: segment grammar ([§6.1][s6-1]), leaving its elements unreachable behind a one-level
7588: diagnostic that blames the wrong child. An empty field reserves nothing: it
7589: reaches no children, its value cannot be told from empty inert parameter data,
7590: and the judgment is per-instantiation, like every wiring judgment.
7591: 
7592: **Spec.** [§8.5][s8-5]
7593: 
7594: **Rationale.** Surfaced by increment 20's cold review: [D-211][d-211]'s collision check
7595: compares the names children actually bear, and the shadow collides with none of
7596: them — the build succeeded while the shadowed container's elements stayed in
7597: the flat list yet became unreachable in wiring resolution, the one-level
7598: rejection reporting them as reaching past the bare child and advising a route
7599: through that child's faces. The empty-field exemption was settled the hard
7600: way: uniform reservation was built first and immediately displaced the
7601: instantiation-dependence onto inert fields, where the refusal is a false
7602: positive — an empty `Tuple`/`NamedTuple` is an empty container and empty inert
7603: parameter data at once, the value cannot tell them apart, and [§8.5][s8-5] keeps empty
7604: containers legal precisely so parametric code needs no special case.
7605: Per-instantiation legality is the norm, not a defect: every wire is validated
7606: against the instance too.
7607: 
7608: **Rejected.**
7609: - *Leaving it to [D-211][d-211]'s duplicate-name check:* it compares the names children
7610:   bear, and the shadow collides with none — a grammar collision, not a name
7611:   collision.
7612: - *Reserving every empty `Tuple`/`NamedTuple` field's name (uniform refusal):*
7613:   built and reverted within the increment — it refuses a bare key over inert
7614:   data where no shadow exists (`Group`'s own empty `wires` beside a child
7615:   named `wires`), trading a true per-instantiation refusal for a false one.
7616: - *A better diagnostic only, admitting the shadow:* the ambiguity is real —
7617:   one grammar answering for two children — and the same instinct as [§8.6][s8-6]'s
7618:   face-name uniqueness invariant applies: ambiguity is refused, not
7619:   documented.
