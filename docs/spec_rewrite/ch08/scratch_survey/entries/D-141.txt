4584: ### D-141 — Continuous state resets are events, owned by the reimplemented PIVector
4585: 
4586: **Status.** ratified
4587: 
4588: **Position.** A continuous component's state reset is an event — a new Appendix
4589: A entry, with the tier asymmetry now taught as a contract: the same-tick reset
4590: entry is marked explicitly discrete-tier, and [§5.3][s5-3]'s gear sentence is extended
4591: to say why. [§3.1][s3-1], [§2.1][s2-1] and [§13.7][s13-7] are unchanged. Even a commanded continuous
4592: reset — the condition arriving as an ordinary `Bool` input, weight-on-wheels
4593: being the shipped instance — is spelled as an event whose guard reads that
4594: input; the discrete tier's input answer does not transfer. Ownership settles on
4595: the reimplemented `PIVector`, which gains a flag-gated reset face: `PIVector(;
4596: reset = true)` adds a `Bool` input face plus the event, the default omits both,
4597: under one fixed policy — rising edge → reset to the declared `init_x` values,
4598: implemented internally as an ordinary guard/handler event (the [Appendix A][sA]
4599: contract's worked instance). The gear wires `strut.wow → frc.reset` (the
4600: touchdown edge).
4601: 
4602: **Spec.** [§2.1][s2-1], [§3.1][s3-1], [§3.3][s3-3], [§10.6][s10-6], [§8.5][s8-5], [§13.7][s13-7], [§5.3][s5-3], [Appendix A][sA]
4603: 
4604: **Rationale.** The reason is semantic, not stylistic: only the discrete tier's
4605: update stage is already a jump map (a reset there is merely another value for
4606: `z⁺`), whereas a continuous state jump must be solver-visible and land between
4607: integration segments — the invariant every hybrid tool enforces (Simulink
4608: zero-crossing plus solver restart, Modelica `reinit` legal only inside `when`,
4609: SUNDIALS stop-and-`ReInit`, DiffEq.jl callbacks), which is also why [§3.1][s3-1]'s
4610: immutable stage views are enforcement of mathematics rather than a
4611: discretionary restriction. No stale-output hazard rides along: [§10.6][s10-6] re-sweeps
4612: outputs to quiescence after handlers, so a continuous edge-reset is
4613: same-boundary by construction. The structural argument is that events are
4614: leaf-owned — a handler resets its own `x`, and assemblies have no events — so
4615: the state's owner is the reset's only possible home, and a cross-component
4616: reset becomes a wired guard input to it. The demand test: genre precedent
4617: counts as demand for a domain block's feature set (external-reset ports on
4618: integrator and PID blocks are standard vocabulary — Simulink, PLC PIDs) even at
4619: a single migration consumer, which is how [§13.7][s13-7]'s grow-by-migration-demand rule
4620: reads past a literal one-consumer count. `strut.wow → frc.reset` gives fresh
4621: regulator state per contact episode, boundary-detected (the regulator's input
4622: ramps from zero at touchdown) and harmless at boundary zero for a sim
4623: initialized on ground. `PistonEngine`'s two `PIVector` instances (`idle`,
4624: `frc`) are verified reset-free in today's code (`piston.jl:295-449`: `f_ode!`
4625: runs both in every engine state, `f_step!` does mode transitions only,
4626: `f_init!` sets gains; windup across unused phases is already handled by the
4627: saturation bounds and `int_halted`) and migrate untouched with the flag off,
4628: their `f_init!` gain writes becoming construction-time parameters ([D-089][d-089]). The
4629: PI law is shared as plain pure functions called by the block's stages ([D-139][d-139]'s
4630: laws-as-plain-functions pattern), and `sat_ext` poses the same
4631: always-on-vs-flag-gated face question, decided at reimplementation time on the
4632: same axis. Recorded as general doctrine, the graduation rule: a wrapper's
4633: pattern moves into the library at the second same-semantics demand.
4634: 
4635: **Rejected.**
4636: - *Superseded position — a gear-owned `FrictionRegulator` leaf wrapping the PI
4637:   law:* it buys a duplicated component whose only job is to keep the library
4638:   block reset-free; leaf ownership already cuts toward the block, since the
4639:   wrapper would have to own the state to own the event, and genre precedent
4640:   supplies the demand a one-consumer count seemed to withhold.
4641: - *An always-on reset face:* taxes every non-user — the engine's two instances
4642:   first — with wire-false ceremony, or leaves an unwired `Bool` face that
4643:   becomes a root slot the frozen roster, the trace header and every condition
4644:   baseline must then speak about.
4645: - *Simulink's full policy menu (rising/falling/either/level triggers plus an
4646:   external-IC port):* one policy suffices, with [§13.7][s13-7]'s Bool gates covering
4647:   falling-edge consumers and separate blocks covering level-pinning and
4648:   reset-to-an-external-value, which is tracking — each extra option is contract
4649:   surface every reader of the block carries forever.
4650: - *The liftoff edge (`!wow`):* behaviorally closest to today's level reset, but
4651:   equivalent only because `Strut`'s no-contact branch returns `v_ec_xy = [0,0]`
4652:   and the integrator leaks — component A's reset correctness resting on
4653:   component B's default branch, precisely the cross-component dependency the
4654:   touchdown edge dissolves rather than documents.
4655: - *Relaxing [§3.1][s3-1]'s immutable views* so stage methods could write `x`: forbidden
4656:   by ODE-solver mathematics, not by taste — trial-point stage evaluations,
4657:   error control and dense-output interpolants all presume in-segment
4658:   continuity, and mid-segment mutation corrupts all three.
4659: - *An assembly wrapping a `PIVector` child and resetting it externally:*
4660:   structurally impossible — events are leaf-owned and an assembly has no
4661:   dynamics of its own, [§3.3][s3-3].
4662: 
4663: **Divergence.** Simulink exposes this as a checkbox; the framework's flag-gated
4664: reset face is "the honest version" — declarations are ordinary functions of the
4665: instance ([§8.5][s8-5]), not an opaque toggle.
