8726: ### D-237 — Classify a non-isbits immutable port type as one opaque leaf
8727: 
8728: **Status.** ratified
8729: 
8730: **Position.** The leaf walk over a port type descends through `Real`s, static
8731: arrays and isbits structs, and stops at an immutable type that is not isbits,
8732: treating it as one opaque leaf: a cell of that type holds the value itself,
8733: reference fields included. An opaque leaf is accepted by identity alone; the
8734: embedding lift ([D-238][d-238]) never enters it. A mutable type anywhere in a port value is
8735: refused (`IllegalPortType`), and so is a handle-typed face surfacing as a
8736: root input.
8737: 
8738: **Spec.** [§4.3][s4-3], [§4.4][s4-4], [§9.5][s9-5], [Appendix C][sC]
8739: 
8740: **Rationale.** [§4.4][s4-4] already fixes the boundary: a bulk-data model is an
8741: immutable struct combining isbits parameters with references to data loaded at
8742: build time and frozen, never a `Ref`. The classification reads that
8743: description off the type, so an author declares nothing and the walk cannot
8744: drift from the prose. The store is the existing one: a handle type is its own
8745: leaf eltype with one homogeneous store, and Julia keeps an immutable struct
8746: with reference fields inline in an array, so the gather and the scatter are
8747: one load and one store, the allocation-free rebuild [§4.4][s4-4] promises. A handle
8748: may carry `T` among its isbits parameters; its cell is then a different type
8749: per activation, produced at `T` by the emitter's stage, and nothing embeds
8750: into it. An opaque leaf has no scalar positions to lift, so the relation
8751: accepts it by identity, and a handle built from literals at a `Dual`
8752: activation is refused at the probe with both types named; the remedy is to
8753: build it at `T`, or to pin the parameter in the declaration. The rule reads
8754: off the outermost type: a struct carrying a handle beside numeric fields is
8755: itself the opaque leaf, and [§4.4][s4-4]'s isbits parameters live inside the handle,
8756: never beside it. The wire relation ([D-236][d-236]) admits a handle at an abstract
8757: entry by the bound clause and needs no arm of its own.
8758: 
8759: A root input of handle type has no synthesis (`probe_value`) and no producer.
8760: Refusing it keeps the field-emitting component, with its value-level
8761: constructor, as the one way bulk data enters a model; a caller-supplied root
8762: handle would be a second injection path, closed for the first cut ([D-008][d-008]).
8763: 
8764: Annotation (2026-09-24): the type walk over a contract substitutes
8765: parameters and never fields, so a handle's references stay frozen with no
8766: stop of their own; a handle with a scalar parameter walks, and "pin the
8767: parameter in the declaration" is spelled `Pinned{Handle{Float64}}`. A
8768: mutable type's parameters pin by rule ([D-263][d-263]).
8769: 
8770: Annotation (2026-09-25): the identity rule governs a store and the producer's
8771: own conformance check. At a wire the entry is a bound, and a frozen opaque
8772: arrival, from a `Pinned` producer or a discrete one, is admitted at an
8773: unpinned entry as the producer's cell ([D-264][d-264]).
8774: 
8775: **Rejected.**
8776: - *An author-declared trait marking handle types:* a second place for the
8777:   boundary [§4.4][s4-4] already states, and one that can drift from it.
8778: - *Walking into the references (the built shape):* `leaf_types` descends into a
8779:   `Vector`'s fields, the build succeeds and the first gather dies in a raw
8780:   `MethodError`, neither supported nor refused.
8781: - *Supplying a handle-typed root input at build:* a second injection path
8782:   beside the value-level constructor, reopening what [D-008][d-008] closed.
