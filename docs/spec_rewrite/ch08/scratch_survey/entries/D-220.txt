7961: ### D-220 — Rename the authoring family to words: stage, update, projection, event and workspace declarations
7962: 
7963: **Status.** ratified
7964: 
7965: **Position.** The component-authoring family drops its single letters and bare
7966: nouns for distinctive words; the spec's formulas keep `f`, `g` and `h` as
7967: mathematical symbols.
7968: 
7969: - `f` → `state_derivative`, `g` → `state_update`.
7970: - `h_x` and `h_s` → `output_state`; `h_xu` and `h_su` → `output_direct`. One
7971:   pair of names serves both tiers, "direct" naming direct feedthrough.
7972: - `project` → `state_projection`, positional shape unchanged.
7973: - `events` → `state_events`, and the pair type `Event` → `StateEvent`.
7974: - `workspace` → `init_workspace`, arity unchanged: `(::C, ::Type{T})`
7975:   continuous, `(::C)` discrete.
7976: - Anything naming a Julia method takes the new word; a symbol in an equation or
7977:   a name for a mathematical object keeps its letter.
7978: - What stays: every bundle field (`x, s, m, u, y, y_x, y_s, t, Δt, ws`); the
7979:   `guard`/`handler` halves and the word "event" in prose; `init_x`, `init_s`,
7980:   `init_m`, `input_types`, `output_types`, `sample_times` and the connection
7981:   declarations; the stage-numbered sweep names of [D-196][d-196]; the executor's
7982:   phase symbol `:project`; the diagnostic kind names, `EventHalfMissing`
7983:   included. No aliases and no deprecation shims: there are no external users,
7984:   and a half-renamed surface is the ambiguity this entry removes.
7985:

7991: **Rationale.** On Julia 1.12 a declaration written without `import Cadence: …`
7992: creates a fresh local generic, silently, whether or not the name is exported,
7993: and the build sees a component that declares nothing. When the author already
7994: owns a function of that name the definition adds a method to *theirs* instead,
7995: and no diagnostic can tell a forgotten import from a legitimate user function —
7996: `f` is the commonest throwaway name in any REPL, `g` is gravity in a flight
7997: package, and `update`, `project` and `events` are ordinary user verbs and
7998: nouns. The work queue's shadowed-declaration diagnostic would have had to hedge
7999: on every one of them. Distinctive names make the check decidable instead: a
8000: foreign binding of `state_derivative` or `init_workspace` in a component's
8001: module is unambiguous evidence of a forgotten import, so the diagnostic can
8002: name it.
8003: 
8004: Two further gains ride along. The underscored suffixes read as subscripts and
8005: suggest partial derivatives, which the stage names never meant; the new names
8006: state the dependence class in words, `output_state` for `y = h(x)` and
8007: `output_direct` for `y = h(x, u)`. And the two output stages are machinery
8008: shared by both tiers, so one pair of names is the honest spelling of what the
8009: compiled sweep blocks already do ([D-196][d-196]).
8010: 
8011: Two earlier rulings retire in part. [D-195][d-195]'s output-stage split (`h_x`/`h_xu`
8012: against `h_s`/`h_su`) goes, and with it the output-stage member of
8013: `DeclarationOnWrongTier` and the "no tier qualifier" reading of the closed
8014: bundle-name sets: `output_state` and `output_direct` take one legal set per
8015: tier again. The tier is still fully determined without them — `init_x` versus
8016: `init_s`, `state_derivative` versus `state_update`, and the `T`-form arity of
8017: `input_types`/`output_types`/`init_workspace` — so a leaf declaring
8018: `state_derivative` beside `init_s` is `StoreWithoutUpdate` or a tier
8019: disagreement exactly as before. [D-195][d-195]'s state-letter split itself stands
8020: untouched. [D-077][d-077]'s rejection of `init_workspace` also goes: it rested on a
8021: workspace not being memory that conditions overlay and on the poison
8022: overwriting it, and [D-183][d-183] removed the poisoning, while `init` in this API
8023: already means *establish* — the device contract's `init!` — rather than
8024: *initial value*, and `init_x`'s own value is a default that conditions overlay.
8025: [D-077][d-077]'s position, declaration by allocation called per activation and per
8026: scratch-store set, stands unchanged. Both entries keep `ratified`: the log has
8027: no partial status, and neither position is replaced. [D-144][d-144]'s naming
8028: convention is amended rather than retired: its class 1 reads *noun phrases*
8029: from here, the stage and update-law names no longer being bare nouns, and the
8030: `workspace` item it flagged for the exported-name audit is settled by this entry.
8031: [D-144][d-144] keeps `ratified` for the same reason.
8032: 
8033: `state_events` also names the distinction [§2.1][s2-1] now teaches. The discrete
8034: tier's ticks, declared by `sample_times`, are *time events*, scheduled because
8035: their instants are known in advance; everything declared through
8036: `StateEvent(guard, handler)` is a *state event*, whose instant is unknown and
8037: must be detected. The criterion is detection versus scheduling, not which
8038: bundle fields a guard reads.
8039: 
8040: Annotation (2026-09-24): `init_workspace` takes the scalar on both tiers and
8041: the contract arities are gone, so the tier is determined by the store every
8042: leaf now declares and the update laws alone ([D-263][d-263]).
8043: 
8044: Annotation (2026-09-25): the words moved from prefix to qualifier when the family was renamed by the bundle field it defines, `x_derivative`, `s_update`, `y_state`, `y_direct`, `x_projection` and `ws_init` ([D-267][d-267]); the shadowing ground and the tier-neutral output stages stand.
8045: 
8046: **Rejected.**
8047: - *Keeping the letters and adding a shadowing diagnostic instead:* the
8048:   diagnostic cannot distinguish a user's own `f` from a forgotten import, which
8049:   is the whole reason the check was never designed.
8050: - *`derivative` and `update` unprefixed:* `derivative` is exported by
8051:   DifferentiationInterface, Polynomials and others; `update` is a common user
8052:   function. Both reintroduce the collision the rename exists to remove.
8053: - *`event_list`, `event_table`, `transitions` for the events declaration:* the
8054:   first two name a container rather than what it holds; "transition" is already
8055:   the spec's word for the crossing itself.
8056: - *`Transition` for the pair type:* same collision with the crossing.
8057: - *`Jump` for the pair type:* spent on the discrete update law's lineage ([§3.2][s3-2])
8058:   and reading as stochastic in the ecosystem.
8059: - *`Callback` for the pair type:* a hook rather than a modeled event, and
8060:   DiffEq's continuous/discrete callbacks use the tier words for what is here
8061:   the detection policy.
8062: - *Keeping `Event`:* `Base.Event` is exported from Base, so a forgotten import
8063:   gives a `MethodError` naming `Base.Event` — loud, but misleading.
8064: - *`alloc_workspace`:* a third prefix for one function, against an `init_*`
8065:   convention the inventory already has.
8066: - *Per-tier output-stage words (a second pair over `s`):* re-creates the split
8067:   this entry retires, to state a tier the rest of the family already states.
