3008: ### D-103 — Detect a binding's sides by method presence at attach
3009: 
3010: **Status.** ratified
3011: 
3012: **Position.** Binding interface: a binding is a value whose type implements
3013: `faces(b)`/`map_input(datum, b)` (input half: enumeration → claim; mapping
3014: arbitrary and never inspected) and/or `selectors(b)`/`map_output(nt, b)`
3015: (output half: [§14.4][s14-4] selectors compiled to one gather at attach); sides detected
3016: by method presence at attach (the [§8.5][s8-5] declaration-shape idiom; `hasmethod` is
3017: public stable API at a service point, not [D-074][d-074]'s internal-reflection seam),
3018: neither side = attach error.
3019: 
3020: **Spec.** [§11.4][s11-4], [§11.6][s11-6], [§8.5][s8-5], [§14.4][s14-4]
3021: 
3022: **Rationale.** No datum-shape contract exists — the datum travels only between
3023: `loop` and `map_input`, same author; binding is an `attach!` argument, never a
3024: device field (narrowing the binding narrows the claim); `TableBinding` is the
3025: one shipped data-driven type (entries in the type ⇒ per-table specialization),
3026: its generic `map_input` owning [§11.4][s11-4]'s conditioning helper; `map_input` purity
3027: taught: cross-datum state lives in the device struct, arrives inside the datum.
3028: 
3029: **Rejected.**
3030: - *Abstract binding-type taxonomy:* resurrects the [§11.6][s11-6] kill one level down; a
3031:   bidirectional binding cannot be two types at once.
3032: - *A declared `sides(b)` trait:* redundant with the methods that must exist,
3033:   one more thing to drift.
3034: - *Per-device custom mapping code as the norm:* the table case is data, not
3035:   code — one framework `map_input` serves every pairing.
