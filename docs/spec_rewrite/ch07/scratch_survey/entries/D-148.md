5086	### D-148 — Select converters per leaf by resolved condition-shape type
5087	
5088	**Status.** ratified
5089	
5090	**Position.** The condition plan's baked converter is selected **per leaf,
5091	keyed by that leaf's type in the resolved condition shape**. Two cases: (i) a
5092	leaf **already at the activation's scalar type** is decision-descended and
5093	takes the type's ordinary `convert`/constructor methods *at that eltype* (an
5094	authored `RQuat` of `Dual`s → the `SVector{4}` state leaf at `Dual`), partials
5095	crossing the write boundary untouched — the trim case, since under a
5096	`Dual`-seeded evaluation of a type-stable `trim_condition(d)` every
5097	decision-dependent leaf is `Dual`-typed in the shape ([§14.7][s14-7]), which is what
5098	makes the seeded decisions reach the sweep at all; (ii) a plain **`Float64`
5099	leaf against a non-nominal activation's scratch** is a held constant and takes
5100	the `Float64 → Dual` zero-partial embedding, whose "held at the operating point
5101	*is* zero partials" justification thereby sits exactly and only on the leaves
5102	where it is true.
5103	
5104	**Spec.** [§9.5][s9-5], [§14.3][s14-3], [§14.4][s14-4], [§14.7][s14-7], [§14.10][s14-10]
5105	
5106	**Rationale.** A round-5 kernel dry-run finding (finding 2; [§14.10][s14-10] unchanged),
5107	reaffirming [D-066][d-066]'s resolution-time bake with its selection rule refined. Leaf
5108	types are **shape facts** — [§14.4][s14-4] already fixes that the tree type carries the
5109	full nesting, every field name *and every leaf type* — so per-leaf selection
5110	consults no runtime fact whatsoever and stays a one-time resolution-time bake,
5111	[D-066][d-066]'s timing exactly. **No new machinery, no new user surface**: under the
5112	seeded evaluation the type system itself classifies decision-descended against
5113	held leaves, so the author writes the same `trim_condition(d)` and the
5114	framework reads the classification off the shape it already compiles against.
5115	**[§14.10][s14-10] needs no amendment** — a linearization operating-point condition is
5116	authored decision-free, so all its leaves are `Float64`-typed and case (ii)
5117	reproduces its behavior by construction — and the surrounding commitments are
5118	intact: [§9.5][s9-5]'s nominal exact-match doctrine for table cells is untouched (at
5119	the nominal activation the activation scalar *is* `Float64`, so case (i) is the
5120	ordinary conversion), and converters still run only on the write paths, never
5121	on state views.
5122	
5123	**Rejected.**
5124	- *A uniform zero-partial embedding for every non-nominal condition write:* the
5125	  prior literal reading of [§14.3][s14-3], and the finding — trim's decision-descended
5126	  leaves arrive at the write boundary already carrying live partials, so the
5127	  strict spelling — a `Float64`-only converter method — raises a `MethodError`
5128	  from inside the baked plan naming no authored line, while the natural robust
5129	  spelling `Dual(value(v), zero(P))` accepts them and strips exactly the
5130	  partials the solve exists to compute, leaving `J ≡ 0` structurally: the
5131	  damping loop stalls, LM *honestly* reports non-convergence on a perfectly
5132	  well-posed problem, `trim!` correctly refuses to commit, and every health
5133	  signal is green (type-stable, zero-alloc, conformance check passing,
5134	  origins clean) with no diagnostic anywhere pointing at the converter —
5135	  after which the derivative-free fallback backend "fixes" the symptom and
5136	  entrenches the defect permanently.
5137	- *Per-write runtime convert decisions:* [D-066][d-066]'s rejected alternative, still
5138	  rejected, and the refinement strengthens the rejection rather than reopening
5139	  it — selection needs no runtime fact at all, the leaf type being a property
5140	  of the very shape the plan is compiled against, so a runtime decision buys
5141	  nothing and costs the unrolled zero-alloc store.
5142	- *Explicit user marking of decision-dependent leaves:* a per-leaf annotation,
5143	  or a second "held"/"seeded" condition vocabulary — redundant with what the
5144	  seeded eltype already proves, and a second source of truth free to drift from
5145	  the actual dataflow — an annotation reading "held" on a leaf the decisions do
5146	  descend into restores the silent zero-Jacobian bug with paperwork on top of
5147	  it.
