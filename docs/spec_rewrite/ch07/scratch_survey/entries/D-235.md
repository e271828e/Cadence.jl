8697	### D-235 — Realize the always-on check at the generated write, against the cell type
8698	
8699	**Status.** ratified
8700	
8701	**Position.** The always-on conformance check ([D-053][d-053]) is one relation, [D-166][d-166]'s
8702	embed-accept, applied at the probe and at every table write. At the write it
8703	holds the return to the type of the cells the stage writes, as the probe fixed
8704	them at this activation, and it is decided when the write's method is generated
8705	over the cell type and the return type.
8706	- Stage returns, `state_derivative`, and the wholesale state writes of
8707	  `state_projection` and a handler's `x` key all take it; the probe's state
8708	  checks apply the same relation.
8709	- A conformant return type generates the straight stores. A non-conformant one
8710	  generates a throw of `ConformanceFailure`, a `StepError` species at runtime
8711	  ([§13.4][s13-4]).
8712	
8713	**Spec.** [§7.1][s7-1], [§9.5][s9-5], [Appendix C][sC]
8714	
8715	**Rationale.** Two facts fix the shape. [D-166][d-166]'s embed-accept makes "types equal
8716	or refuse" impossible at the write: a `Float64` at a declared-`T` cell under a
8717	non-nominal activation is lawful, and storing it into the `T` buffer is the
8718	zero-partial embedding [§9.5][s9-5] describes. So the write cannot be a flat type test;
8719	it is the relation the probe applies, and the leaf store is the embedding. And
8720	the writes are already generated functions over the cell address, whose
8721	parameter is the cell type. Generating them over the return's type as well
8722	evaluates the key-set comparison and the per-leaf relation on types, before any
8723	instruction is emitted. Type-stable conformant code generates the stores it
8724	generates today. Branch-divergent code takes one specialization per return
8725	type, the union split the code already pays. This is [D-053][d-053]'s one baked type
8726	test resolved by dispatch: per-leaf reasoning at generation, no per-field
8727	instruction at runtime, so [D-053][d-053]'s rejection of per-field checks holds in the
8728	sense it was made, which is cost.
8729	
8730	The expected type is stated against the cell rather than against
8731	`output_types(c, T)` so the rule does not depend on how a cell's type is fixed.
8732	Today the two coincide, a cell's type being its producer's declaration
8733	evaluated at the activation; the phrasing survives any later widening of
8734	acceptance.
8735	
8736	Annotation (2026-10-02): [D-166][d-166] is superseded by [D-263][d-263], under which [D-166][d-166]'s
8737	embed-accept relation survives. [D-238][d-238] states it, decided on the type.
8738	
8739	**Rejected.**
8740	- *A runtime `isa` against the declaration's `NamedTuple` type:* refuses the
8741	  `Float64` embed-accept sanctions at a declared-`T` leaf, breaking the
8742	  constant-branch idiom [D-166][d-166] keeps legal.
8743	- *Leaf-count comparison at the probe and no check at the write (the built
8744	  shape):* an `Int64` leaf for a `Float64` state passes and converts, and a
8745	  return field set the probe never saw is dropped or raises a raw `FieldError`
8746	  inside a `StepError`, the shape [D-053][d-053] rejects.
8747	- *Refusing a `Float64` at a declared-`T` cell to force type stability:* a
8748	  `T`-declared output computed from a frozen discrete input is `Float64` at
8749	  every activation, lawfully and stably, so the refusal would require the
8750	  consumer to know its producer's tier, which [D-054][d-054] rules impossible by
8751	  construction. Type stability under `Dual` is an authoring rule ([§7.2][s7-2]), not a
8752	  conformance predicate.
