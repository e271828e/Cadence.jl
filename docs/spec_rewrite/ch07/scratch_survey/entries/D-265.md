10476	### D-265 — Read the `Pinned` marker at the top of an entry alone
10477	
10478	**Status.** ratified
10479	
10480	**Position.** `Pinned{P}` is read at the top of a contract entry and nowhere
10481	else. A marker below the top, in a type parameter (`SVector{2,
10482	Pinned{Float64}}`, `Mixed{Float64, Pinned{Float64}}`), is `IllegalPortType`
10483	on both tiers. A field that must not follow the scalar is typed concretely in
10484	its struct (`b::Float64` beside `a::T`), which freezes it for every user of
10485	the type; a whole leaf is pinned with the marker.
10486	
10487	**Spec.** [§8.2][s8-2], [Appendix C][sC]
10488	
10489	**Rationale.** `retype`'s recursion into type parameters fired the marker's
10490	arm at any depth, so a nested marker was stripped and acted as the
10491	parameter-position pin [D-263][d-263] rejected: `Mixed{Float64, Pinned{Float64}}`
10492	retyped to `Mixed{T, Float64}`. [D-263][d-263]'s ground stands. The spelling is
10493	half-working, because the marker is not `<: Real`, so `Bounded{T<:Real}`
10494	raises a `TypeError` on the same marker `SVector` accepts, and a form that
10495	works on some types and not others is worse than none. It also gave two
10496	spellings for one meaning, `SVector{2, Pinned{Float64}}` beside
10497	`Pinned{SVector{2, Float64}}`. On the discrete tier the declaration is read
10498	as written and the wrong-tier check looks at the top constructor only, so a
10499	nested marker slipped past it, reached the wire pass as a literal type and
10500	failed as a `WireTypeMismatch` that misnamed the fault; unwired, the literal
10501	`Pinned{Float64}` is an empty isbits struct with zero leaves.
10502	
10503	The recorded limit is per-type against per-declaration freezing. The
10504	parameter-position pin would have made the freeze a per-declaration choice,
10505	the same struct with `b` walking in one component's contract and pinned in
10506	another's. The concrete field makes it a per-type choice. That is the right
10507	home for the fact: a field that must not walk is almost always frozen by
10508	nature, a count, a mode flag, a calibration constant, a reference to
10509	build-time data, and the struct definition is where a reader expects to
10510	learn it. The struct's own constructor enforces the freeze on the producer
10511	side, since a stage that hands a `Dual` for a `Float64` field dies in
10512	`convert`, and the wire relation admits `MixedRight{Float64}` at
10513	`MixedRight{Dual}` by embedding at the parameter. One consequence for the
10514	reader's rule: "every `Float64` position follows the scalar" reads the
10515	declaration as written, so a concretely typed field is frozen without
10516	appearing in the contract, the mild reader-opacity [D-263][d-263] accepted for one
10517	walk rule instead of two. `IllegalPortType` is the kind because the offending
10518	type is outside the leaf vocabulary as written, which is what its other arms
10519	name.
10520	
10521	**Rejected.**
10522	- *Admitting the nested spelling as a second legal form:* reopens [D-263][d-263]'s
10523	  rejected item, with the `<: Real` failure and the duplicate spelling it
10524	  recorded.
10525	- *A kind of its own for the nested marker:* `IllegalPortType` already names
10526	  a declared type the vocabulary does not admit, with the declaration and the
10527	  port in its payload.
10528	- *Refusing the nested marker while leaving `retype`'s arm in place:* the
10529	  refusal would guard a walk that still strips at any depth, a latent trap;
10530	  the top-only read removes the arm.
