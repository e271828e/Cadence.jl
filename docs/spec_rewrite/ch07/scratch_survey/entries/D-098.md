2886	### D-098 — Resolve selectors against a source before client policy
2887	
2888	**Status.** ratified
2889	
2890	**Position.** Selector source axis: a selector resolves against a *source*
2891	before any client policy — table selectors
2892	(`get_output`/`get_local`/`get_slot`/`get_face`) against boundary snapshots;
2893	store selectors (`get_state`/`get_deriv`) only against live stores, which only
2894	stopped-sim service evaluations, `capture` and post-run inspection ever hold.
2895	
2896	**Spec.** [§14.4][s14-4]
2897	
2898	**Rationale.** A snapshot-bound reader naming a store selector is an
2899	attach-time `ReadBindingUnresolved` (new `reason` payload field), didactic
2900	style, remedy = declare the field public and read the auto-published port;
2901	[D-083][d-083]'s client split rides on top unchanged, [D-095][d-095]'s family stays closed and
2902	identically spelled.
2903	
2904	**Rejected.**
2905	- *Client-only validation:* [D-095][d-095]'s original "diagnostic readers admit the
2906	  whole family": an output device binding `get_state` passes attach — the
2907	  schema knows the field — then has nothing to gather from at run time, the
2908	  silent-garbage failure attach validation exists to prevent; `get_deriv` worse
2909	  — `ẋ` is integrator scratch, not boundary-consistent.
2910	- *Runtime resolution failure:* defers the error [§11.2][s11-2] and the C172X case study (`flight_case_studies.md`) deliberately moved
2911	  to attach.
2912	- *Snapshots carrying stores to make such bindings resolvable:* [D-038][d-038] stands —
2913	  the source axis enforces it.
