8050	### D-220 — Rename the authoring family to words: stage, update, projection, event and workspace declarations
8051	
8052	**Status.** ratified
8053	
8054	**Position.** The component-authoring family drops its single letters and bare
8055	nouns for distinctive words; the spec's formulas keep `f`, `g` and `h` as
8056	mathematical symbols.
8057	
8058	- `f` → `state_derivative`, `g` → `state_update`.
8059	- `h_x` and `h_s` → `output_state`; `h_xu` and `h_su` → `output_direct`. One
8060	  pair of names serves both tiers, "direct" naming direct feedthrough.
8061	- `project` → `state_projection`, positional shape unchanged.
8062	- `events` → `state_events`, and the pair type `Event` → `StateEvent`.
8063	- `workspace` → `init_workspace`, arity unchanged: `(::C, ::Type{T})`
8064	  continuous, `(::C)` discrete.
8065	- Anything naming a Julia method takes the new word; a symbol in an equation or
8066	  a name for a mathematical object keeps its letter.
8067	- What stays: every bundle field (`x, s, m, u, y, y_x, y_s, t, Δt, ws`); the
8068	  `guard`/`handler` halves and the word "event" in prose; `init_x`, `init_s`,
8069	  `init_m`, `input_types`, `output_types`, `sample_times` and the connection
8070	  declarations; the stage-numbered sweep names of [D-196][d-196]; the executor's
8071	  phase symbol `:project`; the diagnostic kind names, `EventHalfMissing`
8072	  included. No aliases and no deprecation shims: there are no external users,
8073	  and a half-renamed surface is the ambiguity this entry removes.

8080	**Rationale.** On Julia 1.12 a declaration written without `import Cadence: …`
8081	creates a fresh local generic, silently, whether or not the name is exported,
8082	and the build sees a component that declares nothing. When the author already
8083	owns a function of that name the definition adds a method to *theirs* instead,
8084	and no diagnostic can tell a forgotten import from a legitimate user function —
8085	`f` is the commonest throwaway name in any REPL, `g` is gravity in a flight
8086	package, and `update`, `project` and `events` are ordinary user verbs and
8087	nouns. The work queue's shadowed-declaration diagnostic would have had to hedge
8088	on every one of them. Distinctive names make the check decidable instead: a
8089	foreign binding of `state_derivative` or `init_workspace` in a component's
8090	module is unambiguous evidence of a forgotten import, so the diagnostic can
8091	name it.
8092	
8093	Two further gains ride along. The underscored suffixes read as subscripts and
8094	suggest partial derivatives, which the stage names never meant; the new names
8095	state the dependence class in words, `output_state` for `y = h(x)` and
8096	`output_direct` for `y = h(x, u)`. And the two output stages are machinery
8097	shared by both tiers, so one pair of names is the honest spelling of what the
8098	compiled sweep blocks already do ([D-196][d-196]).
8099	
8100	Two earlier rulings retire in part. [D-195][d-195]'s output-stage split (`h_x`/`h_xu`
8101	against `h_s`/`h_su`) goes, and with it the output-stage member of
8102	`DeclarationOnWrongTier` and the "no tier qualifier" reading of the closed
8103	bundle-name sets: `output_state` and `output_direct` take one legal set per
8104	tier again. The tier is still fully determined without them — `init_x` versus
8105	`init_s`, `state_derivative` versus `state_update`, and the `T`-form arity of
8106	`input_types`/`output_types`/`init_workspace` — so a leaf declaring
8107	`state_derivative` beside `init_s` is `StoreWithoutUpdate` or a tier
8108	disagreement exactly as before. [D-195][d-195]'s state-letter split itself stands
8109	untouched. [D-077][d-077]'s rejection of `init_workspace` also goes: it rested on a
8110	workspace not being memory that conditions overlay and on the poison
8111	overwriting it, and [D-183][d-183] removed the poisoning, while `init` in this API
8112	already means *establish* — the device contract's `init!` — rather than
8113	*initial value*, and `init_x`'s own value is a default that conditions overlay.
8114	[D-077][d-077]'s position, declaration by allocation called per activation and per
8115	scratch-store set, stands unchanged. Both entries keep `ratified`: the log has
8116	no partial status, and neither position is replaced. [D-144][d-144]'s naming
8117	convention is amended rather than retired: its class 1 reads *noun phrases*
8118	from here, the stage and update-law names no longer being bare nouns, and the
8119	`workspace` item it flagged for the exported-name audit is settled by this entry.
8120	[D-144][d-144] keeps `ratified` for the same reason.
8121	
8122	`state_events` also names the distinction [§2.1][s2-1] now teaches. The discrete
8123	tier's ticks, declared by `sample_times`, are *time events*, scheduled because
8124	their instants are known in advance; everything declared through
8125	`StateEvent(guard, handler)` is a *state event*, whose instant is unknown and
8126	must be detected. The criterion is detection versus scheduling, not which
8127	bundle fields a guard reads.
8128	
8129	Annotation (2026-09-24): `init_workspace` takes the scalar on both tiers and
8130	the contract arities are gone, so the tier is determined by the store every
8131	leaf now declares and the update laws alone ([D-263][d-263]).
8132	
8133	Annotation (2026-09-25): the words moved from prefix to qualifier when the family was renamed by the bundle field it defines, `x_derivative`, `s_update`, `y_state`, `y_direct`, `x_projection` and `ws_init` ([D-267][d-267]); the shadowing ground and the tier-neutral output stages stand.
8134	
8135	**Rejected.**
8136	- *Keeping the letters and adding a shadowing diagnostic instead:* the
8137	  diagnostic cannot distinguish a user's own `f` from a forgotten import, which
8138	  is the whole reason the check was never designed.
8139	- *`derivative` and `update` unprefixed:* `derivative` is exported by
8140	  DifferentiationInterface, Polynomials and others; `update` is a common user
8141	  function. Both reintroduce the collision the rename exists to remove.
8142	- *`event_list`, `event_table`, `transitions` for the events declaration:* the
8143	  first two name a container rather than what it holds; "transition" is already
8144	  the spec's word for the crossing itself.
8145	- *`Transition` for the pair type:* same collision with the crossing.
8146	- *`Jump` for the pair type:* spent on the discrete update law's lineage ([§3.2][s3-2])
8147	  and reading as stochastic in the ecosystem.
8148	- *`Callback` for the pair type:* a hook rather than a modeled event, and
8149	  DiffEq's continuous/discrete callbacks use the tier words for what is here
8150	  the detection policy.
8151	- *Keeping `Event`:* `Base.Event` is exported from Base, so a forgotten import
8152	  gives a `MethodError` naming `Base.Event` — loud, but misleading.
8153	- *`alloc_workspace`:* a third prefix for one function, against an `init_*`
8154	  convention the inventory already has.
8155	- *Per-tier output-stage words (a second pair over `s`):* re-creates the split
8156	  this entry retires, to state a tier the rest of the family already states.
