12031	### D-289 — Compile cost: generated unrolls, chunks by reference, an unspecialized declaration layer
12032	
12033	**Status.** ratified
12034	
12035	**Position.** Four rules bound what a model costs to compile, beside
12036	[D-086][d-086]'s chunking, and three measures mitigate the rest.
12037	
12038	- Every walk over an entry tuple or a chunk tuple is a generated unroll, one
12039	  statement per element.
12040	- The event set's projection, guard and handler walks chunk as a phase body
12041	  does.
12042	- A barrier takes its chunk by reference. The executor holds one pointer per
12043	  chunk, and it holds the event set by reference.
12044	- The declaration layer takes components unspecialized. Code that runs once
12045	  per build takes a component, an assembly or the root unspecialized and
12046	  does not compile again per component type or per root type, and a closure
12047	  created per component reads the instance from an unspecialized binding. A
12048	  component's own declaration methods still compile per type, and so do the
12049	  helpers that take a declared value such as a connection.
12050	- The mitigations are lazy activations, precompile workloads, and the
12051	  optimization level as an iteration session's knob. A workload bakes the
12052	  generic machinery into the package image, and a component package's
12053	  workload bakes its own types.
12054	
12055	**Spec.** [§9.7][s9-7]
12056	
12057	**Rationale.** Each rule removes a cost measured at `2556df4` by
12058	`docs/reports/20261001_compile_cost_reeval/report.md` (the report below), on
12059	Julia 1.13.0 and Apple Silicon, components with real arithmetic, the minimum
12060	of three runs. With all four in place the trajectories are bit-identical and
12061	every allocation check reads zero.
12062	
12063	A recursion on `Base.tail` allocates at every call once the tuple passes 32
12064	elements. That reached a chunk of more than 32 entries, a body of more than
12065	32 chunks (512 entries at chunk size 16), and an event set with more than 32
12066	projections, guards or handlers. On a model with 64 projecting components it
12067	allocated 595 KB per boundary and made the loop 5 times slower (the report's
12068	section 9). A generated body with one statement per element has no such
12069	limit and compiles faster. The event set's walks were the ones left unchunked, and
12070	chunking them bounds a wide event set's compile cost as it bounds a phase
12071	body's.
12072	
12073	`Chunk`, `PhaseBody` and `EventSet` were immutable and stored inline in the
12074	executor, itself stored inline in the `Simulation`. Each call that passes
12075	one to a non-inlined function emits a copy and a GC root per pointer. On
12076	128 components `evaluate!` compiled to 6 330 LLVM lines with 192 `memcpy`
12077	calls, and to 47 lines with the chunks behind pointers (sections 4.2 and
12078	4.3). Those copies were most of what `init!` and the first `run!` compile per
12079	topology, 16.9 s against 0.5 s with the unroll and the references in place,
12080	and a fifth to a third of the loop's runtime. The rule keeps [D-086][d-086]'s barrier
12081	and makes it hand over a pointer.
12082	
12083	The declaration layer runs once per build and has no performance
12084	requirement. Specialized, it compiled `_walk!`, its closures and the probes
12085	once per component type, and once per root type, because a root's type
12086	spells out its subtree. A closure that captures a typed local is itself
12087	parameterized by that type, so it compiles once per component type even
12088	inside an unspecialized function. Unspecialized, `build` of 64 components of
12089	64 new types falls from 40.5 s to 0.86 s, `build` of a new root of 128
12090	components over known types from 12.1 s to 0.08 s, and the compile per new
12091	component type from 0.42 s to 0.013 s, nearly all of it the component's own
12092	stage methods (section 4.4).
12093	
12094	Chunking keeps [D-086][d-086]'s reason, measured. Chunks of one type share one
12095	compiled function: on 128 components of 2 types the walks compile in 23.2 s
12096	unchunked and 2.8 s at chunk size 16. A function's compile cost grows faster
12097	than its entry count: on 64 components of 64 types the walks compile in
12098	6.4 s unchunked, 3.7 s at 16 and 2.7 s at 4. A topology change that shifts
12099	the entry order compiles every shifted chunk again, 2.4 s on that model at
12100	16 and 1.3 s at 4 (section 4.1). The 2026-07 figures [§9.7][s9-7] carried came from
12101	synthetic bodies, two of them extrapolated to aircraft scale, and their 9 s
12102	`Dual` figure did not reproduce: a `Dual` activation compiled in about the
12103	nominal time (`docs/reports/20260930_compile_cost/report.md`, section 4).
12104	
12105	About 9 s of a cold process is generic machinery, the same for every model,
12106	which a precompile workload moves into the package image. `-O0` about halves
12107	what remains, for a loop 2.3 to 2.8 times slower with the allocation
12108	invariant intact. Its trajectories differ from `-O2`'s by round-off, so a
12109	trace does not replay bit for bit across levels (sections 5 and 10). Lazy
12110	activations stand as [D-086][d-086] had them.
12111	
12112	[D-086][d-086]'s rejection of type-erased call tables stands. The two closure forms
12113	below are its measured instances.
12114	
12115	**Rejected.**
12116	- *`@noinline` at the phase-body call, over a body stored inline:* each call
12117	  site then copies the whole body, larger than the chunks it copied before,
12118	  and the first `run!` on 128 components goes from 12 s to 46 s (the
12119	  report's section 4.2).
12120	- *Phase bodies and the event set behind opaque closures:* 0.5 s per
12121	  topology, for a dependence on an experimental interface and a live
12122	  simulation that no longer sees a redefined method. The FunctionWrappers
12123	  form avoids both and runs 6 to 22 % slower (section 4.5).
12124	- *One opaque closure per entry, walked by a loop:* it removes the
12125	  per-topology compile, but the loop runs 70 % slower on distinct types, and
12126	  the form that does not allocate on Julia 1.13 calls an internal field, the
12127	  internal-ABI dependence [D-086][d-086] rejects (section 4.6).
12128	- *A `Group` without type parameters:* 0.2 to 0.75 s per root once the
12129	  declaration layer is unspecialized, and it changes which service paths
12130	  [D-130][d-130] refuses, because a field declared `::Group` would then pin no
12131	  subtree (section 6).
12132	- *A default chunk size of 4:* about 1 s per topology change on the large
12133	  models, against 3 to 9 % of runtime (section 7).
12134	- *Superseded position — a reduced optimizer level for non-nominal
12135	  activations ([D-086][d-086]'s mitigation ladder):* no measured gain
12136	  (`docs/reports/20260930_compile_cost/report.md`, section 7).
12137	- *Widening the unroll rule to every tuple whose width a model sets:* the
12138	  same cliff sits in the condition plan's walks, a reader's entries and a
12139	  binding's entries (`docs/reports/20261002_tuple_walks/`). The spec already
12140	  promises the outcome where it matters, [§14.4][s14-4]'s zero-allocation write path
12141	  among them, so those walks are defects against their own sections and are
12142	  fixed as such. The technique rests on compiler thresholds that can move
12143	  between Julia versions, so it is recorded in `implementation.md`'s
12144	  authoring caveats and not ruled.
