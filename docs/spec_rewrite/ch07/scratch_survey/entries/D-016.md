581	### D-016 — Uniform component interfaces via `h_x` and per-event re-decode
582	
583	**Status.** ratified
584	
585	**Position.** Uniform component interfaces via the no-feedthrough state decoder
586	`h_x`, with selective auto-publication of declared state/mode fields ([D-035][d-035]);
587	guards and handlers read the fresh boundary table, with per-event re-decode
588	(`handler → project → h_x → h_xu`); `project` is the sole raw-state function
589	(schedule-structural).
590	
591	**Spec.** [§4.2][s4-2], [§5.3][s5-3], [§7.4][s7-4], [§10.6][s10-6], [§8.3][s8-3], [Appendix D][sD]
592	
593	**Rationale.** Recorded only through the rejections below.
594	
595	Annotation (2026-10-02): superseded in part. [D-154][d-154] removes the per-event
596	re-decode and [D-252][d-252] the selective auto-publication. `h_x` as the uniform
597	state decoder and `project` as the sole raw-state function stand.
598	
599	**Rejected.**
600	- *Superseded position — identity publication of state and modes as the
601	  default, plus an unlisted-port convention for interface noise (the earlier
602	  design of record):* retired because contract visibility ([D-034][d-034]) makes
603	  publicity a declaration, and `unlisted` pretended privacy without enforcing
604	  it (hidden but connectable).
605	- *Passing state alongside `y`:* double-passing; two idioms in the wild.
606	- *Fully private discrete state:* breaks uniformity; the codebase culturally
607	  publishes state anyway.
608	- *One-handler-per-component-per-boundary restriction:* the cheap per-event
609	  re-decode removes the need.
610	- *Exposing `z` without an unlisted convention:* RNG/log noise.
611	- *The `unlisted` motivating case — RNG state feeding the component's own
612	  update:* dissolved entirely once [D-035][d-035] gave every function direct `x` views,
613	  so nothing needed publishing to be readable.
