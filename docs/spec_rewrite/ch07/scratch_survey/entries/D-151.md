5236	### D-151 — Canonicalize NamedTuple field order at every author↔framework seam
5237	
5238	**Status.** ratified
5239	
5240	**Position.** **At every author↔framework `NamedTuple` seam the names are the
5241	pairing and field order carries no semantics**. Three canonical orders, each
5242	the *declared* side's: `guess`'s field order for decisions/bounds (and it is
5243	the solver-vector packing order, so "packed by field order" survives, now
5244	well-defined), `tolerances`' for residuals (the residual return canonicalized
5245	to it before packing), `Expected`'s derived order for stage returns — demoted
5246	to an internal fact the author never reproduces. At each seam the framework
5247	canonicalizes by a **type-level reorder** (`NamedTuple{canonical_names}(y)`), a
5248	compile-time permutation of an already-typed value that SROA folds away exactly
5249	where the existing test folds — so [§9.5][s9-5] keeps one whole-type `isa` (never
5250	per-field checks) and [§7.5][s7-5]'s canary verifies the fold empirically.
5251	
5252	**Spec.** [§7.5][s7-5], [§9.5][s9-5], [§14.7][s14-7], [§14.8][s14-8], Appendices B/C/D (as touched)
5253	
5254	**Rationale.** A round-5 kernel dry-run finding (findings 7 and 8): [D-053][d-053]'s
5255	fold economics preserved, [D-118][d-118]'s setup placement kept and its key-set check
5256	completed. The errors are unchanged and are the real ones: key-set mismatches
5257	and per-field type mismatches, `ConformanceFailure`'s diff and
5258	`TrimProblemInvalid`'s payload as they stand; trim-side checks stay at setup,
5259	conformance stays always-on at the table-write point. A permutation is a
5260	non-event.
5261	
5262	**Rejected.**
5263	- *Key-set check plus positional packing:* the prior reading, and finding 7 — a
5264	  permuted `lower` passes the check and applies α's bound to `throttle` — the
5265	  solve searches the wrong box, the report names the wrong variable saturated,
5266	  and the failure is indistinguishable from bad physics; the residual/tolerance
5267	  pair carries the same hazard one step further from the author, its key order
5268	  chosen inside a lambda.
5269	- *Strict identical-`NamedTuple`-type matching with a "same keys, different
5270	  order" directive diagnostic:* sound, but the merge-collision-intolerance
5271	  analogy fails — a merge collision is genuinely ambiguous — two writers, one
5272	  leaf — while a permutation has exactly one sound interpretation, so
5273	  strictness rejects unambiguous input and forces authors to reproduce a
5274	  derived order no single declaration shows them — finding 8's divergence — for
5275	  zero soundness gain, downstream consumption being name-keyed throughout.
5276	- *Per-field checks:* [D-053][d-053]'s rejection stands — canonicalize-then-single-test
5277	  keeps the fold that per-field checking would spend.
