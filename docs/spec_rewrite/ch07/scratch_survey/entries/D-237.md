8815	### D-237 — Classify a non-isbits immutable port type as one opaque leaf
8816	
8817	**Status.** ratified
8818	
8819	**Position.** The leaf walk over a port type descends through `Real`s, static
8820	arrays and isbits structs, and stops at an immutable type that is not isbits,
8821	treating it as one opaque leaf: a cell of that type holds the value itself,
8822	reference fields included. An opaque leaf is accepted by identity alone; the
8823	embedding lift ([D-238][d-238]) never enters it. A mutable type anywhere in a port value is
8824	refused (`IllegalPortType`), and so is a handle-typed face surfacing as a
8825	root input.
8826	
8827	**Spec.** [§4.3][s4-3], [§4.4][s4-4], [§8.2][s8-2], [§9.5][s9-5], [Appendix C][sC]
8828	
8829	**Rationale.** [§4.4][s4-4] already fixes the boundary: a bulk-data model is an
8830	immutable struct combining isbits parameters with references to data loaded at
8831	build time and frozen, never a `Ref`. The classification reads that
8832	description off the type, so an author declares nothing and the walk cannot
8833	drift from the prose. The store is the existing one: a handle type is its own
8834	leaf eltype with one homogeneous store, and Julia keeps an immutable struct
8835	with reference fields inline in an array, so the gather and the scatter are
8836	one load and one store, the allocation-free rebuild [§4.4][s4-4] promises. A handle
8837	may carry `T` among its isbits parameters; its cell is then a different type
8838	per activation, produced at `T` by the emitter's stage, and nothing embeds
8839	into it. An opaque leaf has no scalar positions to lift, so the relation
8840	accepts it by identity, and a handle built from literals at a `Dual`
8841	activation is refused at the probe with both types named; the remedy is to
8842	build it at `T`, or to pin the parameter in the declaration. The rule reads
8843	off the outermost type: a struct carrying a handle beside numeric fields is
8844	itself the opaque leaf, and [§4.4][s4-4]'s isbits parameters live inside the handle,
8845	never beside it. The wire relation ([D-236][d-236]) admits a handle at an abstract
8846	entry by the bound clause and needs no arm of its own.
8847	
8848	A root input of handle type has no synthesis (`probe_value`) and no producer.
8849	Refusing it keeps the field-emitting component, with its value-level
8850	constructor, as the one way bulk data enters a model; a caller-supplied root
8851	handle would be a second injection path, closed for the first cut ([D-008][d-008]).
8852	
8853	Annotation (2026-09-24): the type walk over a contract substitutes
8854	parameters and never fields, so a handle's references stay frozen with no
8855	stop of their own; a handle with a scalar parameter walks, and "pin the
8856	parameter in the declaration" is spelled `Pinned{Handle{Float64}}`. A
8857	mutable type's parameters pin by rule ([D-263][d-263]).
8858	
8859	Annotation (2026-09-25): the identity rule governs a store and the producer's
8860	own conformance check. At a wire the entry is a bound, and a frozen opaque
8861	arrival, from a `Pinned` producer or a discrete one, is admitted at an
8862	unpinned entry as the producer's cell ([D-264][d-264]).
8863	
8864	**Rejected.**
8865	- *An author-declared trait marking handle types:* a second place for the
8866	  boundary [§4.4][s4-4] already states, and one that can drift from it.
8867	- *Walking into the references (the built shape):* `leaf_types` descends into a
8868	  `Vector`'s fields, the build succeeds and the first gather dies in a raw
8869	  `MethodError`, neither supported nor refused.
8870	- *Supplying a handle-typed root input at build:* a second injection path
8871	  beside the value-level constructor, reopening what [D-008][d-008] closed.
