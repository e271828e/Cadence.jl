12504	### D-301 — Name a declaration by what it returns
12505	
12506	**Status.** ratified
12507	
12508	**Position.** A declaration's name says what the declaration returns, its
12509	content, never the consequence its definition has. This is [§8.1][s8-1]'s semantic
12510	axis, and it is how [D-267][d-267] states class 1: "a noun phrase naming what it
12511	returns".
12512	
12513	- `claims(b)` and `reads(b)` keep their names: each names the set it
12514	  returns.
12515	- `exports` stays retired; `u_connections` and `y_connections` name the
12516	  pairs each returns.
12517	
12518	**Spec.** [§8.1][s8-1]
12519	
12520	**Rationale.** [D-146][d-146]'s Rationale read the axis the other way: it renamed
12521	`faces`/`selectors` because they "were content-named where the spec's own
12522	`exports` precedent is consequence-named", and [D-170][d-170] called the
12523	consequence-named family `wires`/`imports`/`exports` "convention-purist".
12524	[D-267][d-267]'s Position later stated class 1 as naming what a declaration returns,
12525	and the declarations on the surface do: `x_init`, `u_types`,
12526	`state_events`, `inner_connections`, `sample_times`, `ws_init`, `claims`,
12527	`reads`. [§8.1][s8-1] held both readings at once after a move inverted one of its
12528	sentences. This entry settles on the one the surface follows, so no name
12529	changes.
12530	
12531	Annotation (2026-10-02): [D-303][d-303] renames the connection declarations
12532	`inner_wires`, `input_wires` and `output_wires`. Each still names the pairs
12533	it returns, so the axis and the second bullet's ruling stand.
12534	
12535	**Rejected.**
12536	- *Consequence naming ([D-146][d-146]'s Rationale):* naming the role a declaration
12537	  plays. Under it the `*_connections` family was a recorded exception, and
12538	  the `*_init` and `*_types` declarations, which name what they return,
12539	  read as exceptions too.
