## §7.5
- V41. The allocation policy is not dogma. [D-014]
- V42. Three reasons support it; only one is about speed. [D-014]
- V43. Reason 1: GC-pause jitter control for real-time.
- V44. Reason 2: throughput for unattended runs.
- V45. Unattended runs = runs with empty staging and no snapshot readers (gloss).
- V46. Reason 3: the canary. An unexpected allocation is Julia's most reliable symptom of type instability.
- V47. A zero baseline therefore makes @allocated == 0 a CI-testable invariant.
- V48. That invariant catches inference regressions at the offending commit.
- V49. (Pointer) section states scope, three tiers, what the log does not record, tools for unavoidable garbage.
- V50. The zero-allocation invariant is scoped to the stepping loop. [D-135, §14.8]
- V51. The stopped-sim services were always allocation-tolerant. [D-135, §14.8]
- V52. Publication is not a phase body. [D-288, §9.7]
- V53. Publication's one snapshot allocation per boundary sits with logging on the framework side of that scope. [§11.2]
- V54. The policy has three tiers.
- V55. Continuous hot path = per-stage evaluation plus everything else that runs unconditionally per frame or boundary.
- V56. Those unconditional items are guards (evaluated every boundary whether they fire or not) and x_projection at both its §5.3 positions in the execution order.
- V57. **Budget exactly zero, CI-enforced** at the phase-body seam that phase_bodies exposes. [§9.7, D-014, D-116]
- V58. Periodic ticks and event handlers execute episodically; a tick runs when due, a handler only on firing.
- V59. Their allocation is zero by idiom.
- V60. The idiom is workspace (component-declared mutable scratch arriving as ws bundle field) and snapshot pattern, plus immutable-value returns.
- V61. The rare exception has a documented tolerance. [D-116]
- V62. The seam's granularity scopes the tolerance per body, so it never loosens the continuous assertions. [D-116 by position]
- V63. Logging is amortized-zero.
- V64. The log retains the published snapshot objects themselves, by reference. [§11.2, D-137]
- V65. It keeps one slot per retained boundary and makes no copy.
- V66. sizehint! to the retention bound makes regrowth a non-event.
- V67. The allocation claim is about the snapshot's fields, not everything reachable from them.
- V68. A model carrying §4.4 field handles (immutable query objects consumers evaluate at their own arguments, e.g. heightmap terrain, wind grids) has a snapshot type with reference fields. [§4.4]
- V69. Those fields ride as references to build-time-frozen data, no copy, no per-boundary garbage.
- V70. That is what the allocation claim asserts; it does not assert snapshot is isbits.
- V71. Per-boundary allocation cost is zero either way.
- V72. Summarize-or-skip rule governs what such a field contributes on export. [§4.4]
- V73. Event firings are not recorded.
- V74. The log holds boundary snapshots; the trace holds staged inputs. [§11.2, §11.5]
- V75. Neither carries a per-event record.
- V76. Replay plus the published modes recovers which events fired at which boundary.
- V77. The honest remedy is to declare the mode field public and return it from y_state. [§11.2, D-252]
- V78. A mode field so exposed is in every snapshot.
- V79. An event-firing stream is a guarded addition (a capability the design admits but does not build).
- V80. Two tools serve where garbage is unavoidable.
- V81. Arena allocation (Bumper.jl-style) serves scoped temporaries.
- V82. A scheduled GC.gc(false) at frame boundaries moves collection out of the critical path.
- V83. Julia has no per-object freeing, so these are the honest levers.
